# 伙伴方向性步态与施工转身

## 原因

- `AvatarPlayerModel` 以前只配置手持物品姿势，腿部完全沿用原版 `PlayerEntityModel` 的前后摆动，没有横移方向分量。
- `AccessBuildExecutor` 的施工短边移动直接写水平速度，没有像原版 `MoveControl` 那样转身；空闲看玩家/四处张望的 Goal 还可能在施工时争抢视线。
- 短边固定 `0.1` 格/tick，没有复用导航的工程师等级与实体速度属性倍率。原版步行动画虽然也读取位移，但不能区分真正走路与施工传送、同格对齐。

## 改动

- 共用 `LocomotionGait`，每个伙伴独立保存状态，客户端每 tick 读取实际水平位移。相位按走过的距离推进，渲染只插值，不依赖 FPS 或期望速度；被墙挡住时不继续积累步数。
- 位移投影到身体朝向，生成前进、后退、左右横移、斜向混合。后退反转前后摆腿，横移使用侧向摆腿；方向切换、身体角度跨越 ±180° 和步态相位回绕均处理插值。
- 慢速小步、快速大步：完整左右脚周期的行程为 `clamp(0.75 + 8 × 每 tick 位移, 0.75, 2.7)` 格，摆角由玩家模型 0.75 格腿长估算。停止时摆幅收敛到零。不是逐脚落点锁定/膝关节 IK，也不宣称完全消除所有地形上的滑步。
- 短边移动每次最多转身 18°，清理遗留前向/侧向输入，头部跟随行进方向。空闲看向 Goal 在任务、导航和战斗中让位。
- 宽阔平地的短边速度复用等级、实体属性倍率；窄路、近站位、脚手架仍保留 `0.1` 格/tick 上限，普通短边最高 `0.2`，且不超过剩余距离。垂直速度与碰撞处理不改动。
- 施工传送、80-tick 兜底校正、同格对齐统一携带同步修正序号。客户端排除修正及随后三 tick 的位置插值；同位置重复施工不会反复发送修正。大幅未标记跳位也会重置步态。
- 裤腿、衣袖和护甲复制新的骨骼姿态。持工具手臂保留较小摆幅；使用物品、拉弓、挥工具/攻击的上肢姿势不覆盖。游泳、骑乘、攀爬、飞行、睡眠等仍使用原版动画。

## 范围与验证

步态适用于所有职业的 `AvatarEntity`，与建筑家族无关。施工朝向和速度改动位于共用施工执行器；不修改施工规划、安全边界、材料支付、保护检查和进度持久化。

自动验证入口：`tools/validate_locomotion.ps1`（默认 JDK 21，目标 Java 17）。

- JUnit：方向投影、斜向归一、位移/步幅/步频、静止、FPS 无关、相位回绕、传送、非地面状态、实体独立、方向反转、护甲/服装骨骼同步、工具/弓姿势、速度倍率和窄路限速。
- GameTest：真实实体转身、真实执行器步行且未触发传送、微小校正同步、非步行姿势隔离；并回归脚手架、工程师通行、墓园/市政厅和施工恢复支付契约。
- 全量 `test build` 后生成未筛选 GameTest 入口的发布 JAR。日志和 XML 位于 `build/locomotion-validation/`。

这些是数值模型与无界面服务端验证，不能替代实际客户端观感验收。未自动替换玩家实例的模组或修改存档。多人游戏需客户端和服务端同步更新（新增了实体修正序号的同步字段）。
