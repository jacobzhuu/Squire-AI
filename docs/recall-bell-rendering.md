# 召集铃视觉修复

召集铃的 16 个职业/品质变体和基础回退模型统一继承
`assets/squire/models/item/recall_bell_body.json`。

旧资源把完整透明图标铺在双面矩形上，再手工拼接逐像素侧面、
横跨 16 单位的细边框及独立职业色块。背面图像与侧面轮廓也没有
采用一致的镜像方向。这些结构不再用于召集铃渲染。

新外观是一个紧凑的立体铃铛，由 8 个封闭长方体组成：木柄、金色铃身、
品质饰边、铃舌和正反面职业徽记。UV 按各面的尺寸取样，全部限制在
所属纹理的 0–16 范围内；所有几何位于单个物品的 0–16 范围内。
纹理均来自 Minecraft 1.20.1 内置资源，无自定义渲染器。

- 未绑定时徽记为金色；普通绑定为白色，守卫为蓝色，工程师为橙色。
- 四种品质继续使用灰色、紫晶、钻石、黄金饰边。
- 第一人称左右手采用原版物品的镜像变换及 0.68 缩放；第三人称为 0.55。
- 背包使用轻微旋转以呈现铃铛体积，掉落物及物品展示框共用相同模型。
- 原始 PNG 保留，但模型不再引用它。NBT、绑定、职业、品质谓词和 Tooltip 未修改。

## 自动验证

使用 Java 21 启动 Gradle：

```powershell
$env:JAVA_HOME = 'C:/Program Files/Java/jdk-21'
./gradlew.bat test --tests dev.squire.client.render.RecallBellAppearanceTest build
```

回归检查覆盖 16 种谓词选择、公共模型继承、几何和 UV 范围、材质引用、
左右手变换，以及职业和品质颜色区别。

## 客户端验收

资源测试和打包不等同于游戏实机渲染验证。安装新 JAR 并重新启动客户端后，
检查两种职业的四档品质，以及未绑定召集铃：背包、快捷栏、第一人称主副手、
第三人称、掉落物和物品展示框。预期均为紧凑立体铃铛，无矩形底板、长边框、
透明图标侧边或悬浮的大色块。确认 Tooltip 和已有侍从绑定仍正常。
