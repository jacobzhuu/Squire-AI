# 工程师地下与高空施工通路

工程预览现在会规划可执行的开挖和脚手架步骤。地下目标不再要求玩家事先挖通道路；高空目标即使只有一层，也会根据工程师所在高度规划登高通路。

- 地下施工：从现有入口逐步开挖两格高的阶梯通路，保留返回入口的路线。实际开挖使用背包工具、消耗耐久，掉落物收入背包，放不下的留在世界中。通路不会自动回填。
- 高空施工：深于自动地基填补范围的干燥空气间隙作为高空工程处理，不再强制填一根土柱。脚手架从真实支撑处搭起，按原版稳定距离检查、实际备料，完工后回收。
- 预览：蓝色表示脚手架，橙色表示开挖位置；工程页显示开挖数量。水平通路范围仍最多外扩 6 格，垂直范围延伸到工程师所在高度并受世界高度限制。
- 安全：容器、基岩、流体、落沙顶棚和受保护方块不会被通路开挖直接破坏；不挖掉工程师当前的支撑，也不破坏已完成的建筑来抄近路。
- 恢复：开挖步骤、脚手架归属、入口和进度随工程快照保存。世界修改使用工程结算检查点，工具不足会暂停，补齐后可继续。
- Windows 存档：替换工程存档时若短暂出现 `AccessDeniedException`，最多尝试 5 次，总等待不超过 100 毫秒；其他写入错误和持续拒绝仍按原流程暂停，不能跳过结算检查点。

已确认的旧工程继续使用其原有快照；要为原先无法规划的预览生成新路线，需要重新选择或调整预览位置。

对应测试位于 `M33ScaffoldingGameTests`（真实地下开挖、高空单格施工、脚手架回收和危险方块）与 `ConstructionSnapshotTest`（跨高度开挖步骤持久化）。

2026-09-11 初次验证中，人工水域施工曾在场地准备阶段报材料不足。后续已修复优惠账单的零成本步骤检查，通路、地基和流体施工合计 27 项 GameTest 全部通过，包括该人工水域测试、市政厅和市场摊位。完整结果保存在 `build/reports/gametest/engineer-material-sites-validation.xml`，修复说明见 [工程开挖与材料阻塞修复](engineer-material-and-site-fixes.md)。
