# 工程师移动与石材烧制坊验收修复

工程师在宽阔平地上的移动倍率为一级 1.00，每级增加 0.05，十级 1.45。
施工普通寻路、施工站位移动、挖掘赶路使用同一等级配置。
窄通道、上下台阶和脚手架仍保留减速与碰撞约束；迅捷特质仍由实体属性应用一次。

石材烧制坊 Tier 1 的实际游戏日志显示：施工结束时三扇云杉木门的
`open=true`，而蓝图的 `open=false`，造成反复验收失败。
门的开关与红石供电状态现在视为使用状态；材质、朝向、门轴和上下半部仍严格匹配。
初次放置仍采用蓝图中的状态，已结算的门不会因被打开而重新收费。
移除或替换门仍会被识别，不允许免费重造。

调度器重试时保留具体失败原因，验收未满足使用 `POSTCONDITION_NOT_MET`，
不再把真实故障覆盖为 `RETRYING`。

旧工程无需重新生成蓝图或改写账单：加载更新后的模组，再点击重新检查／继续即可
重新判断已建好的门。此修复不直接修改玩家存档。

回归测试包含一级和十级的石材烧制坊完整施工，以及打开门后的验收、账单恢复、
错误朝向与材质拒绝、已付费方块不可免费重造和重试原因保留。

验证结果：838 项单元测试全部通过，正式 JAR 构建成功。一级、十级完整施工和
门状态回归均有通过记录；最终版本复跑时，Windows 对测试世界的
`projects.json.tmp -> projects.json` 替换偶发返回 `AccessDeniedException`，
导致部分整组运行触发 `CONSTRUCTION_RECOVERY_REQUIRED` 而未全绿。
没有绕过存档失败保护，也没有把此环境问题计为施工测试通过。
