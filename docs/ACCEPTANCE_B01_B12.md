## 0. 一次性准备

### 0.1 开关（三个功能默认关闭，这是有意的 §94）

```
/squire admin worldedit enable     # B07 需要
/squire admin automation enable    # B09 需要
/squire admin cbp enable           # B10 需要
```

`/squire admin automation enable` 的状态会持久化，重启后仍然开着（这本身是 B09 的一条验证）。另外两个默认每次开服都是关的。

### 0.2 权限

单人开启作弊 / 服务器 OP（权限等级 2）**自动拥有全部权限节点**，不需要手动 grant。非 OP 玩家需要：

```
squire.world.edit    # B07
squire.automation    # B09
```

### 0.3 LLM

B12 需要模型；其余 11 条**全部可在无 LLM 的情况下完成**（走 FastPath）。

```
/squire admin llm            # 查看当前配置（key 已脱敏）
/squire admin llm reload     # 改完 config/squire/llm.json 后热重载
```

### 0.4 ⚠️ 已知缺口：无法在不经过 LLM 的情况下把物品交给伙伴

目前没有命令或 FastPath 能把玩家背包里的东西交给伙伴（`inventory.pickup_nearby` 只对模型开放）。**这影响 B04 和 B06 的准备步骤。**

变通办法（按推荐顺序）：

1. **让它自己采**（最真实，也最符合验收精神）：B04 的铁镐链路本来就包含采矿采木，直接说那句话即可。
2. **丢在地上 + 让模型捡**：把物品丢到伙伴脚边，说"把旁边的东西捡起来"，模型会调用 `inventory.pickup_nearby`。需要 LLM。
3. B06 的治疗物品（金苹果/治疗药水）无法采集，只能用办法 2。

记录这条缺口本身也是有价值的验收产出。

### ☐ B12　使用第三方 Tool 查询机器状态

| | |
|---|---|
| **前置** | 需要 **LLM 已配置**，且需要一个真实的第三方数据源（二选一，见下） |
| **输入** | 例如 `查一下那台机器现在什么状态` |
| **应看到** | 一句**可读摘要**，例如 `factory:machine_status：status=running，energy=812` |
| **必须验证** | 玩家看到**具体状态值**；模型能**基于这个值继续回答**；聊天里不是一坨 JSON |
| **禁止作为证据** | 只有 outcome listener 收到了值 |

**数据源二选一**：

- **A（推荐）MCP 服务器**：编辑 `config/squire/mcp.json`（`/squire admin mcp reload` 会先生成一份全部禁用的示例），填好 `url` 或 `command`，把 `enabled` 改成 `true`，再 `/squire admin mcp reload`。用 `/squire admin mcp list` 和 `/squire admin mcp status <名字>` 确认已连接。
- **B 第三方 mod**：任何通过 `squire` entrypoint 注册只读工具的 mod。

> 注意：内置的 `example:echo` 只是把你发的话原样回显，**不足以作为 B12 的证据**（它不返回机器状态）。它可以用来验证"数据能回到玩家和模型"这条通路，但不要拿它当 B12 打勾。
