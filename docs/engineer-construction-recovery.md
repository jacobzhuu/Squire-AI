# 工程师施工恢复

施工通路现在是执行方式的选择，不再把“必须步行到达并返回固定入口”作为所有建筑的开工前提。

## 根因

- 旧规划器按固定次序施工，并要求每一步都能回到同一个入口。墓园围墙、墓穴台阶和市政厅封闭结构会切断这个返回条件；扩大搜索范围不能消除这种结构性冲突。
- 执行器先检查历史站位，再检查目标是否已经完成。地基填入旧站位后，即使目标方块已就位，也会反复报告不可达。
- 原版导航在新放置地板、脚手架和门附近可能停滞或反复重试；以前某些分支只有失败退出，没有统一的施工恢复路径。回收阶段也错误地依赖步行返回条件。
- 目录保留了旧资格评审的失败原因，修复规划器后仍可能禁用模板。目录必须使用新的真实评审证据重新生成。
- 新增的辅助记录还需兼容旧档和远距离工程师：执行方式与恢复计数属于进度，不能改变已付费操作的标识；保存的站位占位值不能越过已确认范围。

## 恢复机制

正常工程仍逐格行走、开挖和搭建脚手架。通路搜索失败后，规划器保留已规划步骤，把后续工作标记为辅助施工；执行中站位失效时先寻找替代站位，移动连续 100 tick 未接近目标时重算一次路线，再启用辅助。辅助优先把工程师移动到能够完成该步骤的安全站位；没有近处站位时，从工程范围内的安全位置执行服务端逐格操作。

支撑、身体碰撞、附近生物、世界边界、区块加载和操作后的站位会重新检查。地基、主体、清场、流体和设施回收使用相同的辅助站位逻辑。取水仅使用已授权的水源。永久建筑仍使用原有账单、工具和原版放置依赖；没有使用 `/fill` 或整栋粘贴。

## 已有工程

- 点击原来的“继续”会恢复因通路阻塞暂停的工程；蓝图几何、方向、已付费操作和临时设施归属保持原值。
- `/squire blueprint recover` 为当前选中的工程启用恢复并继续。未确认预览只重新检查，仍通过原来的确认入口开工。
- `/squire blueprint diagnose` 只读显示阶段、目标、原站位、规划原因、恢复次数和待结算写入，不触发重规划。
- 已完成的步骤先检查目标，包括门和床的完整组合，再决定是否需要站位；旧站位被地基覆盖不再阻挡已完成步骤。
- 存档版本升级到 9；旧工作步骤默认使用步行方式，首次加载旧版本时保留 `.pre-v9.bak`。进度中的辅助状态独立于按内容哈希保存的几何。

## 仍需处理的真实阻塞

材料或工具不足、权限拒绝、不安全开挖、生物占用、区块未加载、没有安全安置位置、流体围护缺口，以及无法确定的结算仍会暂停并说明原因。辅助施工不会免费重建已付费后被移除的方块。受保护或仍支撑玩家脚手架的临时设施保留归属和待退款记录。辅助站位搜索不主动加载邻接区块。

Windows 对蓝图存档的短暂文件锁复用工程存档的有界重试：最多 5 次，累计等待最多 100ms。持续拒绝及其他 I/O 错误仍失败，不跳过写入检查点。

## 验证入口

- `ConstructionRecoveryGameTests`：直接调用真实施工执行器，验证远程操作仍遵守权限、材料、付费后损坏检查、持久化失败和回收归属。
- `M40ConstructionRecoveryGameTests`：墓园 Tier 5 西向、市政厅 Tier 2 西向，以及旧站位和远程施工的完整工程。
- `M41ConstructionMatrixGameTests`：两个家族、5 个 Tier、标准／平台、4 个朝向，共 80 项；从“已启用辅助恢复”的状态实际完成施工与回收，覆盖恢复方式对每种拓扑的适用性。自动发现阻塞由 M40 单独覆盖。原本不支持的资源明确记录 `UNSUPPORTED`，不能计为已建成。
- `M30CatalogQualificationGameTests`：全目录的方块组合、通路与原版物理资格检查，分别记录辅助步数和失败原因；这份结果不代替真实 NPC 完整施工测试。

构建和测试使用 JDK 21，产物字节码仍兼容 Java 17 / Minecraft 1.20.1。

可用 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/validate_construction_recovery.ps1` 重跑完整验证。脚本依次运行资格评审、根据证据更新目录、检查生成资源可复现、运行矩阵和回归，最后恢复未筛选的模组清单并执行单元测试与发布构建。任一阶段失败即停止。日志和 XML 报告保存在 `build/construction-validation/`；仅重建专用 GameTest 世界，不接触游戏实例或玩家存档。
